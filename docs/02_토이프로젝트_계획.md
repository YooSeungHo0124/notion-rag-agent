# 토이 프로젝트 계획: "JobFit Agent" — 채용공고 분석 & 지원 코칭 멀티에이전트

> 목표: `01_AI_Agent_직무분석.md`의 체크리스트(Tool calling, LangGraph, RAG, 벡터DB, 메모리, 멀티에이전트, MCP, 평가, 트레이싱, FastAPI/Docker)를 **하나의 프로젝트로 모두 증명**한다.

## 1. 무엇을 만드나

사용자가 질문하면 에이전트 팀이 응답하는 서비스입니다.
- "AI Agent 신입 공고에서 제일 많이 요구하는 기술이 뭐야?" → RAG로 수집된 공고를 검색해 근거와 함께 답합니다.
- "내 이력서로 네이버 AI 에이전트 공고에 지원하면 부족한 게 뭐야?" → 공고와 이력서를 비교해 갭 분석과 학습 로드맵을 만듭니다.
- "LangGraph 공고 새로 올라온 거 있어?" → MCP 도구로 공고를 수집하고 갱신합니다.

이 주제를 고른 이유는 두 가지입니다. 실제 데이터(공고)가 있어서 RAG와 평가가 의미 있고, 결과물 자체가 취업 준비에 도움이 됩니다.

## 2. 구독 Claude로 LLM을 호출하는 방법

### 방식: Claude Code 헤드리스 모드 (`claude -p`)
Claude Code에 구독 계정으로 로그인해 두면, 프로그램에서 CLI를 서브프로세스로 호출할 수 있습니다.

```bash
claude -p "질문" --output-format json --model sonnet
claude -p "질문" --mcp-config ./mcp.json --allowedTools "mcp__jobs__*"   # 내 MCP 도구 사용
```

```python
# llm/claude_cli.py — 모든 LLM 호출은 이 어댑터 하나만 거친다
import json, subprocess
def ask(prompt: str, system: str = "", mcp_config: str | None = None) -> str:
    cmd = ["claude", "-p", prompt, "--output-format", "json"]
    if system: cmd += ["--append-system-prompt", system]
    if mcp_config: cmd += ["--mcp-config", mcp_config]
    out = subprocess.run(cmd, capture_output=True, text=True, check=True)
    return json.loads(out.stdout)["result"]
```

### 주의할 점
- **개인 학습·로컬 실행 용도로만** 쓰세요. 구독 로그인을 다른 사람에게 서비스로 제공하는 것은 Anthropic 정책상 허용되지 않습니다. 공개 데모나 배포가 필요하면 API 키로 바꿔야 합니다.
- 사용량 한도(5시간 단위 리밋)가 있습니다. 평가 셋을 대량으로 돌릴 때는 쉽게 소진됩니다.
- 한 번 호출할 때마다 프로세스가 새로 떠서 수 초가 걸립니다. 그래서 에이전트 노드 수를 적게 설계하는 편이 좋습니다.
- **어댑터 패턴이 핵심입니다.** `LLMClient` 인터페이스를 `ClaudeCLIClient`와 `AnthropicAPIClient` 두 구현으로 두면, 나중에 설정 한 줄로 API로 전환할 수 있습니다. 면접에서 설명할 거리도 됩니다.
- Claude는 임베딩 모델을 제공하지 않습니다. 그래서 **임베딩은 로컬 모델**(예: `BAAI/bge-m3`, 한국어 지원)을 쓰고, 이 부분은 비용이 들지 않습니다.

### Tool calling은 어떻게?
CLI 래퍼로는 LangChain의 `bind_tools`를 그대로 쓰기 어렵습니다. 그래서 역할을 이렇게 나눕니다.
- **도구 = 내가 만든 MCP 서버.** Claude Code가 MCP 도구를 네이티브로 호출합니다. tool calling과 MCP를 동시에 증명할 수 있습니다.
- **흐름 제어 = LangGraph.** 각 노드가 `ask()`를 호출하고, 라우팅 결정은 JSON 출력을 파싱해서 합니다.

## 3. 아키텍처

```
[사용자] → FastAPI (/chat)
              │
        LangGraph StateGraph
              │
         ┌─ Supervisor (의도 분류·라우팅, JSON 출력)
         │
         ├─ Researcher Agent ── RAG 검색 (Chroma/Qdrant + bge-m3)
         ├─ Collector Agent  ── MCP 서버 "jobs" (fetch_postings, save_posting, search_db)
         ├─ Analyst Agent    ── 공고 ↔ 이력서 갭 분석 (구조화 JSON)
         └─ Writer Agent     ── 최종 답변 + 출처 인용
              │
        Memory: 대화 단기 메모리(LangGraph checkpointer, SQLite)
                사용자 프로필 장기 메모리(이력서·관심직무)
              │
        Tracing: Langfuse(셀프호스트) 또는 JSON 로그
```

## 5. 단계별 로드맵 (각 단계가 끝날 때마다 동작하는 결과물이 남도록)

| 단계 | 기간(목안) | 목표 | 증명하는 역량 |
|---|---|---|---|
| **M0** | 0.5일 | `claude -p` 어댑터 + 단순 Q&A CLI | LLM 연동, 어댑터 설계 |
| **M1** | 2일 | 공고 20~50건 수집(수동 또는 크롤링) → 청킹·임베딩 → Chroma → "근거 인용 Q&A" | **RAG, 벡터DB** |
| **M2** | 2일 | MCP 서버 `jobs` 구현(search/save/fetch) 후 Claude가 도구로 사용 | **MCP, Tool calling** |
| **M3** | 3일 | LangGraph로 Supervisor와 Researcher·Analyst·Writer 구성, 이력서 갭 분석 | **LangGraph, 멀티에이전트** |
| **M4** | 1일 | 대화 메모리(checkpointer)와 사용자 프로필 장기 메모리 | **Memory** |
| **M5** | 2일 | 평가셋 30문항(질문·정답 근거), 검색 정확도(Recall@k)와 답변 품질(LLM judge) 측정, 개선 전후 비교 | **Evaluation** ← 차별화 포인트 |
| **M6** | 1일 | 트레이싱, FastAPI, Docker Compose, README·아키텍처 다이어그램 | **Observability, 배포** |

## 7. 포트폴리오 어필 포인트
1. **"구독 CLI와 API를 바꿔 끼울 수 있는 LLM 어댑터"**: 비용을 의식한 설계라는 점을 보여줄 수 있습니다.
2. **평가 수치**: 예를 들어 "청킹 전략을 바꿔 Recall@5를 0.62에서 0.81로 개선"처럼 구체적인 숫자를 제시합니다.
3. **MCP 서버 직접 구현**: 공고에서 우대사항으로 자주 등장합니다.
4. 트레이스 화면 캡처와 아키텍처 다이어그램
