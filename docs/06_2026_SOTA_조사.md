# 2026 RAG 스택 SOTA / 대중화 모델 조사

- 조사일: 2026-11-10
- 질문: 객체탐지에서 YOLO처럼 **"성능이 좋고 대중화되어 표준처럼 쓰이는"** 모델과 기법이 RAG 쪽에도 있는가?
- 주의: 출처의 상당수가 블로그나 벤더 순위입니다. 리더보드 점수가 **한국어 개인 노트 검색 성능을 보장하지는 않습니다**. 그래서 최종 선택은 우리 평가셋(F6)으로 결정합니다.

---

## 1. 임베딩 모델

| 모델 | 위상 | 라이선스 | 크기 / VRAM(fp16, 대략) | 비고 |
|---|---|---|---|---|
| **Qwen3-Embedding (0.6B / 4B / 8B)** | **2025~2026 오픈 임베딩의 사실상 표준 ("YOLO 포지션")** | Apache 2.0 | 0.6B 약 1.5GB / 4B 약 8GB / 8B 약 16GB | 다국어, 32K 문맥. 8B는 출시 당시 MTEB 다국어 70.58. 지금은 신규 모델에 밀림 |
| harrier-oss-v1 (Microsoft, 27B / 0.6B) | 2026년 10월 기준 MTEB 다국어 1위로 보도 | MIT | 27B는 로컬 불가 / 0.6B 소형 | 0.6B가 Qwen3-8B에 근접한다는 보도가 있으나 **독립 검증 부족** |
| Granite Embedding Multilingual R2 (311M) | 경량 다국어 | Apache 2.0 | 매우 작음 | 다국어 점수 65.2 |
| **bge-m3** | 검증된 "안전한 기본값" | MIT | 약 2GB | **dense와 sparse를 동시 생성**하는 유일한 대중 모델. 하이브리드 검색에 유리 |

**결론:** 대중성과 성능을 함께 보면 **Qwen3-Embedding**이 YOLO 포지션입니다. RTX 5080 16GB 기준으로는 **4B가 성능과 자원 사이의 적정점**입니다. 8B는 리랭커와 동시에 올리기 어렵습니다.

## 2. 리랭커

| 모델 | 위상 | 라이선스 | 비고 |
|---|---|---|---|
| **Qwen3-Reranker (0.6B / 4B / 8B)** | **오픈 리랭커 성능 상한** | Apache 2.0 | BEIR nDCG@10 기준 8B 61.81 vs bge-v2-m3 56.42 (제3자 논문). MTEB-R 기준 4B 69.76 vs bge 59.51 (Qwen 자체 보고) |
| **bge-reranker-v2-m3** | 가장 많이 쓰이는 기본값 (다운로드 약 1,890만 건) | Apache 2.0 | 568M, 빠름 |
| Querit-Reranker-4B | 2026 신규, 다국어 평균 1위 주장 | — | 독립 검증 부족 |
| jina-reranker-v3 | 성능 좋음 | **CC BY-NC (상업 이용 불가)** | 개인 프로젝트에는 무방 |

**결론:** 대중적인 기본값은 **bge-reranker-v2-m3**, 성능 상한은 **Qwen3-Reranker-4B**입니다.

## 3. 벡터DB
- 2026년 자료에서도 별도의 "새 표준"은 확인되지 않았습니다. Qdrant, Milvus, pgvector, Weaviate가 계속 주류입니다.
- **Qdrant 유지.** 사유는 `05_스택_재검토.md`에 정리했습니다 (sparse와 dense 하이브리드, 서버 쪽 결과 결합, 필터, 로컬 파일 모드).

## 4. 기법 (방법론) — 2026 사실상 표준 파이프라인

| 기법 | 2026 위상 | 적용 여부 |
|---|---|---|
| **하이브리드 검색 (dense + sparse/BM25)** | "사실상 운영 표준", 순수 dense보다 대부분 우수 | ✅ 기본 적용 |
| **리랭킹 (약 50개 후보 → 상위 5개)** | 하이브리드 다음 단계로 보편화 | ✅ 기본 적용 |
| **Agentic / Adaptive RAG**: 질의 난이도에 따라 바로 답변, 1회 검색, 여러 단계 반복 검색 중 선택 | 2026 오케스트레이션의 핵심 변화 | ✅ LangGraph Supervisor로 구현 (F4) |
| **질의 재작성 (Multi-turn)**: "아까 그거"를 독립 질의로 변환 | SemEval-2026 등에서 효과 확인 | ✅ 적용 |
| Contextual chunking: 조각에 문서 맥락을 앞에 붙임 | 효과는 알려져 있으나 LLM 호출 비용이 큼 | △ **저비용 버전**: 페이지 제목, 제목 경로, 날짜를 조각 앞에 붙임 (LLM 불필요) |
| GraphRAG | 관계형·전역 질의에 유용 | ⏸ 2차 |
| Late-interaction (ColBERT 계열) | 정밀하지만 인덱스가 큼 | ✗ 이 규모에서는 이득이 작음 |

## 5. 최종 채택안 (기존 대비 변경점)

```
노션 → 제목 구조 기준 분할 + [제목/경로/날짜] 맥락 접두어
     → dense: Qwen3-Embedding-4B   ─┐
     → sparse: bge-m3 sparse        ─┤→ Qdrant (하이브리드, RRF 결합)
질의 → (재작성) → 하이브리드 상위 50 → 리랭커 → 상위 5 → Claude
```

| 구성요소 | 기존 | **변경 후 (기본값)** | 평가(F6)에서 비교할 후보 |
|---|---|---|---|
| Dense 임베딩 | bge-m3 | **Qwen3-Embedding-4B** | bge-m3, Qwen3-Emb-0.6B, harrier-0.6B, KURE-v1 |
| Sparse | bge-m3 sparse | bge-m3 sparse (유지) | 한국어 형태소 분석 기반 BM25 (kiwipiepy) |
| 리랭커 | bge-reranker-v2-m3 (실험용) | **bge-reranker-v2-m3 기본 적용** | Qwen3-Reranker-0.6B / 4B |
| 벡터DB | Qdrant | Qdrant (유지) | — |
| 파이프라인 | 단순 RAG | **하이브리드 + 리랭크 + 질의 재작성 + Adaptive 라우팅** | 각 단계 유무에 따른 비교 실험 |

**VRAM 예산 (RTX 5080 16GB):** Qwen3-Emb-4B(약 8GB) + bge-m3(약 2GB) + bge-reranker(약 1GB) ≈ 11GB로 동시 상주가 가능합니다. Qwen3-Reranker-4B로 바꾸면 임베딩은 0.6B로 낮추거나 모델을 순차 로딩해야 합니다.

**어필 포인트:** "2026 대중 SOTA 조합(Qwen3 계열)과 검증된 기본값(bge)을 **내 한국어 데이터로 직접 비교**해 채택했다"는 것을 수치표로 제시합니다.
