# UI/UX 및 답변 신뢰도(Grounding) 설계

- 작성일: 2026-11-10
- 컨셉: "내 노션을 소스로 쓰는 NotebookLM"에 쓰기 작업, 자동 동기화, 평가를 더한 것

---

## 1. UI/UX (NotebookLM 참고)

```
┌──────────────┬──────────────────────────────┬──────────────┐
│ 소스 패널     │ 채팅                          │ 작업 패널     │
│ □ 전체 노션   │ Q: GPU OOM 어떻게 해결했지?    │ ⏳ 승인 대기  │
│ ☑ 프로젝트DB  │ A: 배치를 16→8로 줄이고 [1]     │  - 페이지 생성 │
│ ☑ 회의록      │    gradient checkpointing [2]  │   [미리보기]   │
│ □ 개인메모    │    신뢰도: ● 높음 (3/3 문장 근거)│   [승인][거절] │
│ 동기화: 3분 전│ ─ 출처 ─                       │ 📌 저장한 답변 │
│ [지금 동기화] │ [1] 학습로그 9/12 › OOM 대응 ↗  │ 🧪 평가 결과   │
└──────────────┴──────────────────────────────┴──────────────┘
```
- **소스 패널:** 검색 범위를 페이지나 DB 단위로 선택합니다 (Qdrant 필터로 처리). 동기화 상태도 표시합니다.
- **채팅:**
  - 답변을 스트리밍(SSE)으로 받습니다.
  - 인용 번호 `[n]`에 마우스를 올리면 원문 조각을 보여주고, 클릭하면 **노션 해당 블록으로 바로 이동**합니다 (`notion.so/<page>#<block_id>`).
- **작업 패널:** 쓰기 작업 승인 대기열, 저장한 답변, 평가 결과를 둡니다.
- **기술:** React + Vite + TypeScript + Tailwind와 FastAPI(SSE)를 씁니다. 화면은 `127.0.0.1`에서만 엽니다.

## 2. 출처 링크를 정확하게 만드는 방법
- 동기화할 때 조각(chunk)마다 `page_id, block_ids[], page_title, heading_path, url, last_edited_time`을 함께 저장합니다.
- 인용 링크는 페이지가 아니라 **블록 단위**로 만들어, 클릭하면 근거 문단으로 바로 이동합니다.
- 답변 생성은 **구조화 출력**으로 받습니다. LLM이 링크를 직접 쓰게 하지 않고 chunk ID만 고르게 한 뒤, 링크는 내 코드가 붙입니다. 이렇게 하면 **링크가 날조될 수 없습니다**.

```json
{"sentences": [
  {"text": "배치 크기를 16에서 8로 줄였다", "citations": ["c_81f2"]},
  {"text": "gradient checkpointing을 켰다", "citations": ["c_81f2","c_0a91"]}],
 "answerable": true}
```

## 3. 신뢰도를 판단하는 방법 (4단계)

| 단계 | 확인 내용 | 방법 | 비용 |
|---|---|---|---|
| ① 검색 신뢰도 | 관련 기록이 있기는 한가 | 리랭커 최고 점수가 임계값보다 낮으면 답변 대신 **"기록에 없음"** 처리 | 무료 (이미 계산함) |
| ② 인용 유효성 | 인용한 chunk가 실제로 검색된 것인가 | 코드로 대조 (결정적) | 무료 |
| ③ 문장별 근거 검증 | 각 문장이 인용한 원문에 의해 **뒷받침되는가** | 기본: 로컬 리랭커로 (문장, 인용 조각) 점수 계산 → 근거 있음 / 부분 / **근거 없음** 표시. 정밀 모드: Claude 판정(LLM-as-judge) | 기본 무료 / 정밀은 Claude 호출 1회 |
| ④ 최신성·충돌 | 오래된 기록인가, 기록끼리 다른 말을 하는가 | `last_edited_time` 표시, 출처들이 서로 다른 내용이면 날짜와 함께 둘 다 제시 | 무료 |

**화면 표시**
- 답변마다 신뢰도 배지를 붙입니다: ● 높음 / ◐ 보통 / ○ 낮음. 기준은 근거가 있는 문장 비율, 검색 점수, 최신성입니다.
- 근거 없는 문장은 **노란 밑줄**로 표시하고, "기록에서 확인되지 않음"을 툴팁으로 보여줍니다.
- 근거가 아예 없으면 지어내지 않고 "기록에 없습니다. 이런 키워드로 찾아볼까요?"로 응답합니다.

**한계를 명확히 해 둡니다:** 신뢰도는 "**내 노트에 근거하고 있는가**"를 뜻합니다. "사실인가"가 아닙니다. 노트 자체가 틀렸다면 답도 틀립니다. 이 점을 UI 문구로도 안내합니다.

## 4. 오프라인 평가 (F6에 추가)
| 지표 | 의미 |
|---|---|
| Faithfulness | 답변 문장 중 근거로 뒷받침되는 비율 |
| Citation precision / recall | 인용이 정확한가, 필요한 근거를 빠뜨리지 않았는가 |
| Abstention 정확도 | 기록에 없는 질문에 "모른다"고 답한 비율 |
| 판정기 보정 | 리랭커 판정이 Claude 판정이나 내 수동 라벨과 얼마나 일치하는가 |

→ 어필 문장 예시: "문장 단위 근거 검증을 넣어 Faithfulness를 X%에서 Y%로, 근거 없는 답변을 Z건에서 0건으로 줄였다."
