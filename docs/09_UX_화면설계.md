# UX 및 화면 설계 (v2)

- 작성일: 2026-11-10
- 이전 설계: [08_UI_및_답변신뢰도_설계](08_UI_및_답변신뢰도_설계.md) (NotebookLM식 3단 고정)
- 이 문서의 목적: 1차 구현을 실제로 써 보면서 드러난 문제를 반영해서, **"실제로 어떻게 쓰는가"부터 다시 설계**합니다.

---

## 0. 한 줄 정의

> **내 업무 기록에서 답을 찾고, 그 답이 어디서 왔는지 바로 대조할 수 있는 개인 연구 도구**

- 가치는 "AI가 답해 준다"가 아니라 **"내 기록에서 왔고, 어디인지 바로 확인할 수 있다"**에 있습니다.
- 그래서 디자인의 중심축은 **답변 ↔ 원문(노션) 대조**입니다.

## 1. 사용자와 사용 맥락

| 항목 | 내용 |
|---|---|
| 사용자 | 나 1명. AI/비전 엔지니어. 노션에 업무 일지·트러블슈팅·설치 문서·실험 기록 600여 페이지 |
| 장소 | 업무 중 데스크톱. 모니터 1~2대, 터미널·IDE·노션과 함께 띄워 둠 |
| 빈도 | 하루 수 회 ~ 수십 회, **짧게 묻고 바로 돌아감** |
| 기대 | 빨리(체감 10초 안), 정확하게, 출처 확인은 클릭 한 번 |
| 기기 | 데스크톱 우선. 모바일(이동 중 확인)은 읽기 위주의 보조 수단 |

## 2. 핵심 사용 시나리오 (빈도순)

### S1. 기억 찾기 — "그때 그 값 뭐였지?" (가장 많음)
> 서버 작업 중 "TECH_SEE v3 backend 포트가 몇이었지?", "OOM 났을 때 batch 몇으로 줄였지?"

1. 단축키로 바로 입력 → 2. 결론 한 줄 확인 → 3. (가끔) 출처 클릭해서 원문 확인 → 4. 값을 복사해 작업으로 복귀
- **필요한 것:** 결론이 맨 위에 있어야 함, 값 복사, 진행 표시, 짧은 대기
- **없어도 되는 것:** 긴 설명, 표, 스튜디오

### S2. 대조·검증 — "이거 진짜 내 기록 맞아?"
> 답의 수치가 예상과 다를 때, 기록이 여러 개라 헷갈릴 때

1. 의심 가는 문장의 출처 번호 클릭 → 2. **원문의 해당 위치**가 옆에 열림 → 3. 다른 출처로 넘겨 가며 비교 → 4. 필요하면 노션에서 직접 수정
- **필요한 것:** 출처 → 원문 위치 이동, 여러 출처 전환, 기록 불일치 경고, 실제 노션 창 열기
- **이 서비스만의 차별점이 드러나는 시나리오입니다.**

### S3. 정리·비교 — "흩어진 기록 모아줘"
> "batch/카메라 수별 fps 비교", "쓰러짐 모듈 지금까지 시도한 방법 정리"

1. 질문 → 2. 표·흐름도·단계로 정리된 답 → 3. 후속 질문으로 좁혀 감 → 4. 결과를 저장하거나 노션에 기록
- **필요한 것:** 블록형 답변, 후속 질문, 대화 맥락 유지, 저장/내보내기

### S4. 기록하기 — "이거 노션에 남겨줘" (가끔)
1. 에이전트 모드로 요청 → 2. **무엇을 어디에 쓸지 미리보기** → 3. 승인/수정/거부 → 4. 결과 링크
- **필요한 것:** 승인 카드(대상 페이지·내용 미리보기), 실행 결과 링크

### S5. 다시 보기 — "어제 물어본 거"
- **필요한 것:** 대화 기록, 검색

## 3. 1차 구현의 문제 (직접 사용하며 확인)

| 문제 | 원인 | 방향 |
|---|---|---|
| 소스 패널이 쓸모없음 | 634개 평면 목록, "(제목 없음)"·"-"·"07 : 00" 같은 일지 행이 수백 개 | 기본 숨김. 범위 선택은 검색형 팝오버 + 상위 폴더/DB 묶음 |
| 출처 확인 시 흐름이 끊김 | 클릭하면 노션 새 탭이 계속 쌓임 | 재사용 노션 창 + 화면 안 원문 뷰어 |
| 신뢰도가 개발자용 숫자 | "근거 확인 12/12 · 검색 점수 0.88" | 말로 표현("근거 충분")하고, 숫자는 펼쳐야 보이게 |
| 대화가 새로고침하면 사라짐 | 서버에 대화 기록 없음 | 대화 기록 저장 + 사이드바 목록 |
| 말풍선 UI | 챗봇 관행 | 답변은 "문서"이므로 질문은 제목, 답변은 본문 |
| 대기 9~25초 | 블록이 많아지며 출력이 길어짐 | 진행 단계 + 블록 순차 표시. 결론 블록부터 먼저 |
| 면책 문구 반복 | 답변마다 출력 | 설정/도움말로 이동하고, 처음 한 번만 안내 |

## 4. 정보 구조

```
앱
├─ 사이드바
│   ├─ 새 질문 (Ctrl+K)
│   ├─ 대화 기록 (오늘 / 이번 주 / 이전, 검색)
│   ├─ 저장한 답변
│   └─ 하단: 검색 범위 · 동기화 상태 · 설정
├─ 대화 (메인)
│   ├─ 질문 (제목)
│   ├─ 답변 문서 (블록) + 출처 표시 + 신뢰도 한 줄
│   ├─ 후속 질문
│   └─ 입력창 (하단 고정, 에이전트 토글, 범위 칩)
└─ 출처 패널 (오른쪽, 필요할 때만)
    ├─ 출처 탭 (이 답변의 출처들)
    ├─ 원문 뷰어 (인용 블록 하이라이트)
    └─ "노션에서 열기" (재사용 창)
```

## 5. 화면 프레임

### 5.1 기본 상태 (출처 패널 닫힘)

```

│             │        TECH_SEE_V3 전체 시스템 구조가 어떻게 돼?            │
│ ＋ 새 질문 ⌘K│        ─────────────────────────────────────            │

│             │                                                          │

│             │        → 로그는 어디서 확인해?                             │
```

- 질문은 **말풍선이 아닌 문서 제목**(20px, semibold)입니다. 답변은 그 아래 본문입니다.
- 출처 표시는 문장 끝의 작은 위첨자 번호(¹²)입니다. 지금의 원형 칩보다 가볍게 만듭니다.
- 신뢰도는 한 줄입니다: `● 근거 충분 · 출처 4 ⌄`. 펼치면 문장별 근거 점수와 검색 점수가 보입니다.

### 5.2 출처 대조 상태 (S2 — 핵심 화면)

출처 번호나 `출처 4`를 누르면 오른쪽 패널이 열립니다. 대화 영역은 그만큼 좁아집니다.

```
┌──────┬──────────────────────────────────┬──────────────────────────────────────┐
│ (접힘)│ TECH_SEE_V3 전체 시스템 구조?       │ ¹구동 방법  ²install 문서  ³  ⁴Docker │
│  ◧   │ ──────────────────────────        │ ──────────────────────────────────── │
│  ＋   │ ┃ 4개 프로세스를 PM2로 관리 ¹       │ TECH_SEE_v3 install on Ubuntu 24.04  │
│  ⌕   │                                  │ › 8. 전체 구동 순서                    │
│      │ Vision의 `.env` 키는 backend의     │ 2026-06-17 수정       노션에서 열기 ↗  │
│      │ ▒EVENT_API_KEY와 같아야 합니다. ²▒ │ ──────────────────────────────────── │
│      │      ↑ 선택한 출처의 문장 강조      │ ## 7. 환경 변수                        │
│      │ Frontend는 … ²                    │ backend/.env …                        │
│      │                                  │ ┃ EVENT_API_KEY=…  ← 인용 블록 하이라이트│
│      │                                  │ ┃ vision/.env 의 키와 동일하게          │
│      │                                  │ ## 8. 전체 구동 순서                    │
│      │                                  │ …                                    │
│      │                                  │                        ‹ 이전  다음 › │
└──────┴──────────────────────────────────┴──────────────────────────────────────┘
          가변 (최소 480px)            ⇔ 드래그로 폭 조절 (기본 44%)
```

- **양방향 연결:**
  - 출처를 고르면 그 출처를 인용한 문장이 강조됩니다.
  - 문장의 번호를 누르면 원문의 해당 블록으로 스크롤되고 하이라이트됩니다.
- **탭 = 이 답변의 출처들.** 다른 질문의 출처는 섞지 않습니다(맥락이 흐려지므로).
- **원문 뷰어:** 노션 API로 페이지를 가져와 우리 스타일로 렌더링합니다(제목, 목록, 코드, 표, 토글, 콜아웃).
  - 노션은 `x-frame-options: SAMEORIGIN`이라 iframe으로 넣을 수 없습니다(헤더로 확인).
- **노션에서 열기:** 이름이 정해진 창(`window.open(url#block, "nra-notion")`) 하나를 재사용합니다. 출처를 바꿔 눌러도 창이 쌓이지 않고 그 위치로 이동합니다.
  - OS 분할(`Win+→`)로 띄워 두면 진짜 노션과 나란히 볼 수 있습니다.
  - 설정에서 "노션 데스크톱 앱으로 열기(`notion://`)"를 선택할 수 있습니다.
- 공간 확보를 위해 패널이 열리면 사이드바가 아이콘 레일(56px)로 자동으로 접힙니다.

### 5.3 답변 생성 중 (대기 체감 줄이기)

```
  batch_size랑 카메라 대수별 fps 비교해줘
  ─────────────────────────────────
  ✓ 노트 검색 · 8개 조각 (쓰러짐 모듈 가능 대수, techseev3 CPU 병목 …)
  ● 답변 작성 중 ━━━━━━━━━━░░░░  7초
  ○ 근거 검증

  ┃ ░░░░░░░░░░░░░░░░░░░░░░░░░░░░   ← 결론 자리 스켈레톤
  ░░░░░░░░░░░░░░░░░░░░░
```
- 검색이 끝나면 **찾은 문서 제목**을 바로 보여줘서, 맞는 곳을 찾고 있는지 사용자가 먼저 판단하게 합니다.
- 블록은 검증이 끝나는 대로 위에서부터 차례로 나타납니다(150ms 페이드).
- 중단 버튼을 둡니다(Esc).

### 5.4 근거 없음 (거절)

```
  ⓘ 내 노트에서 근거를 찾지 못했습니다
     가장 가까운 기록: "쓰러짐 모듈 가능 대수 확인" (관련도 낮음)
     [이 페이지 열기]  [다른 표현으로 다시 묻기]  [범위 넓히기]
```
- 거절도 **다음 행동**을 주는 화면이어야 합니다. 빈손으로 끝내지 않습니다.

### 5.5 에이전트 승인 (S4)

```
  ┌ 노션에 기록하기 전에 확인해 주세요 ───────────────────────────┐
  │ 대상   TECH_SEE_V3 Docker  (페이지 끝에 추가)                 │
  │ 내용   ┌──────────────────────────────────────────────┐    │
  │        │ 2026-11-10 롤백 절차 재확인 …  (편집 가능)       │    │
  │        └──────────────────────────────────────────────┘    │
  │ 이유   사용자가 "방금 내용 Docker 페이지에 추가"를 요청         │
  │                                   [거부]  [수정 후 실행] [실행] │
  └──────────────────────────────────────────────────────────────┘
  ▸ 실행 과정 2단계 (노트 검색 → 페이지 읽기)            ← 기본 접힘
```
- 내용 편집 후 승인은 백엔드에서 이미 지원합니다(`resume(args=…)`).
- 실행 후에는 "추가됨 · 노션에서 보기 ↗"로 결과 위치를 바로 엽니다.

### 5.6 범위 선택 (소스 패널 대체)

```
  범위: 전체 ▾  → 팝오버
  ┌───────────────────────────────┐
  │ ⌕ 페이지 검색                   │
  │ ◉ 전체 노트 (634)               │
  │ 최근 사용                        │
  │ ○ TECH_SEE_v3 (8개 페이지)       │
  │ ○ 쓰러짐 모듈 (5)                │
  │ 폴더 / 데이터베이스               │
  │ ▸ 업무 일지 (312)  ← 일지 행은 묶음 │
  │ ▸ 트러블슈팅 (96)                │
  │ ▸ 모델 학습 (74)                 │
  └───────────────────────────────┘
```
- 선택하면 입력창 위에 칩(`범위: TECH_SEE_v3 ✕`)이 붙습니다. 범위를 바꿨다는 사실을 놓치지 않게 하기 위해서입니다.

### 5.7 모바일 (≤ 768px)
- 사이드바는 왼쪽 서랍, 출처 패널은 **아래에서 올라오는 시트**(높이 85%)입니다.
- 입력창은 하단 고정이고 키보드에 맞춰 올라갑니다. 표는 가로 스크롤, 흐름도는 세로 배치입니다.

## 6. 상호작용 규칙

| 동작 | 결과 |
|---|---|
| `Ctrl+K` | 어디서든 새 질문 입력 |
| `Ctrl+/` | 에이전트 모드 토글 |
| `Esc` | 생성 중단 / 출처 패널 닫기 |

## 7. 비주얼 스타일 — "조용한 연구 도구"

**원칙:** 장식이 아니라 **정렬·여백·타이포그래피**로 품질을 냅니다. 색은 의미가 있을 때만 씁니다.
- 참고: Linear(밀도와 절제), Notion(문서 감각), Perplexity(출처 배치)

### 7.1 디자인 토큰

| 토큰 | 라이트 | 다크 | 용도 |
|---|---|---|---|
| `--bg` | #FFFFFF | #0F1012 | 본문 배경 |
| `--bg-subtle` | #F7F7F5 | #17181B | 사이드바, 패널 |
| `--border` | #E7E6E3 | #26282C | 구분선, 카드 |
| `--text` | #1F1F1E | #E8E8E6 | 본문 |
| `--text-muted` | #6B6A67 | #9A9A97 | 보조 |
| `--accent` | #4F46E5 | #8B85FF | 출처 번호, 링크, 포커스 (강조색 1개) |
| `--accent-soft` | #EEF0FF | #1E1F3A | 결론 박스, 선택된 문장 |
| `--ok` / `--warn` / `--bad` | #15803D / #B45309 / #B91C1C | 밝게 보정 | 신뢰도·주의·불일치에만 |
| `--hl` | #FFF4C2 | #3A3410 | 원문 뷰어 인용 하이라이트 |

- **글꼴:** Pretendard Variable(본문·UI), JetBrains Mono(코드·수치)
- **글자 크기:** 본문 15.5px / 줄간격 1.75, 질문 제목 20px 600, 소제목 16px 600, 보조 13px, 출처 번호 11px
- **간격:** 4px 단위 (4·8·12·16·24·32·48)
- **모서리:** 카드 10px, 버튼·입력 8px, 칩 999px
- **그림자:** 없음. 떠 있는 요소(팝오버·미리보기 카드)에만 `0 8px 24px rgb(0 0 0 / .08)`
- **움직임:** 120–180ms ease-out. 블록 등장, 패널 열기/닫기, 하이라이트 페이드만 사용

### 7.2 블록별 스타일

| 블록 | 스타일 |
|---|---|
| 결론 | 왼쪽 3px `--accent` 선 + `--accent-soft` 배경, 16px medium |
| 본문 문장 | 일반 텍스트. 근거 약함은 점선 밑줄 + hover 시 이유 |
| 표 | 얇은 테두리, 헤더 `--bg-subtle`, 숫자 열 오른쪽 정렬·고정폭 숫자 |
| 코드 | `--bg-subtle`, 언어 라벨 + 복사, 줄 번호 없음 |
| 단계 | 번호 원(20px, `--accent`) + 세로 연결선 |
| 흐름도 | 노드 카드 + 화살표, 노드 설명 12px muted |
| 주의/불일치 | 아이콘 + 라벨 + 연한 배경. 불일치는 **어느 기록이 어떻게 다른지** 두 줄로 |
| 차트 | 가로 막대, 값 라벨 오른쪽, 출처 수치 아님 시 경고 테두리 |

### 7.3 신뢰도 표현

| 내부 값 | 표시 |
|---|---|
| high | `● 근거 충분` (ok색 점) |
| medium | `◐ 일부만 확인` (warn색 점) — 확인이 필요한 문장 수 함께 표시 |
| low | `○ 근거 약함` (bad색 점) — "출처를 직접 확인하세요" |
| 거절 | `ⓘ 기록 없음` 화면(5.4) |

- 숫자(문장별 점수·검색 점수)는 `⌄`를 펼치면 보입니다. 평가할 때나 디버깅할 때만 필요하기 때문입니다.

### 7.4 하지 않을 것
- 말풍선, 아바타, 이모지 아이콘
- 그라데이션 배경, 유리 효과, 카드마다 다른 색
- 답변마다 반복되는 면책 문구
- 기본 노출된 소스 목록

## 8. 구현 순서

| 단계 | 내용 | 효과 |
|---|---|---|
| 1 | 디자인 토큰 + 레이아웃 골격(사이드바 / 대화 / 출처 패널), 말풍선 제거, 다크모드 정리 | 전체 인상이 바뀜 |
| 2 | **출처 패널**: 원문 뷰어(노션 API 블록 렌더) + 인용 블록 하이라이트 + 양방향 연결 + 재사용 노션 창 | 핵심 가치(S2) |
| 3 | 대화 기록 저장·목록·검색 | S5, 새로고침해도 유지 |
| 4 | 범위 선택 팝오버(폴더/DB 묶음, 일지 행 묶기) | 소스 패널 문제 해결 |
| 5 | 신뢰도 한 줄 표현, 거절 화면 개선, 승인 카드 개선 | S1·S4 마무리 |
| 6 | 블록 순차 표시 + 생성 중단, 단축키 | 대기 체감 개선 |

각 단계가 끝날 때마다 실제 질문 10개로 S1~S4를 직접 써 보고, 걸리는 지점을 이 문서에 기록합니다.
